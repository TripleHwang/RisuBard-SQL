# RisuVault v0.3.1 성능 릴리스 체크리스트

이 절차는 자동화된 계약 테스트를 보완하는 실제 기기 게이트입니다. 모든 데이터는 생성된 중립 문자열만 사용하며 사용자 대화, 캐릭터 이름, 프롬프트, 자산 URL을 기록하거나 첨부하지 않습니다.

## 준비

- Device A: iPhone 13+ / iOS 17+에서 Safari와 설치된 PWA를 각각 확인하고 Tailscale로 서버에 연결한다.
- Device B: Android Chrome, Node 환경, Tailscale 연결을 확인한다.
- 데이터: 생성된 200 characters, 20,000 messages, logical 20 GiB asset catalog를 사용한다.
- 측정 전 서버 버전·커밋과 기기 OS/브라우저 빌드를 결과표에 적는다.

## 각 기기에서 수행

1. 앱 데이터가 없는 상태에서 10 cold starts를 수행하고 시작 시간 샘플을 저장한다.
2. 생성된 서로 다른 채팅을 20 chat switches 수행하고 선택 시간 샘플을 저장한다.
3. 30 minutes 동안 스크롤, 스트리밍, 이미지 활동을 반복한다. 개발 패널의 content-free performance-report JSON과 서버 max RSS만 보관한다.
4. 생성된 3 GiB `.risum`을 가져온다. 업로드 중 한 번 취소하고, asset processing 중 한 번 취소한 뒤, 마지막 실행은 완료시킨다.
5. 강제 종료·WebKit termination·forced reload·draft 손실·부분 모듈·고아 공개 자산·스테이징 정리 상태를 pass/fail로 기록한다.

릴리스는 시작 p95가 8초를 넘거나 채팅 선택 p95가 1.5초를 넘으면 차단됩니다. hydrated chats 2개, mounted messages 60개를 넘는 관찰 결과도 차단 사유입니다.
