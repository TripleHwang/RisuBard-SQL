# 리스바드 메모리 사용 안내

리스바드 메모리는 대화에서 확정된 장기 정보를 Markdown 문서로 보관하고, 다음 응답에 필요한 문서만 골라 사용하는 작업 공간입니다. 채팅 원문과 위키 문서는 역할이 다릅니다. 채팅 원문은 근거로 남고, 위키는 인물·장소·사건처럼 다시 사용할 정보를 정리합니다.

## 자동 분석과 추가 분석

- 답변은 다음 사용자 메시지가 정상적으로 생성되거나 사용자가 직접 확정할 때 분석 대상이 됩니다.
- 자동 분석은 확정된 내용에서 사건과 지속적으로 기억할 정보를 찾아 위키에 반영합니다.
- **추가 분석**은 최신 응답 가운데 아직 적용되지 않은 정보를 다시 검사합니다. 이미 적용된 정본은 제외하므로 누락 점검에 사용할 수 있습니다.
- 분석이 실패해도 채팅 원문은 사라지지 않습니다. 상단의 상태 메시지와 **로그**에서 원인을 확인할 수 있습니다.

## 화면 구성

- **작업 공간**: 문서 목록, Markdown 편집기, 위키 관리자 명령을 함께 표시합니다.
- **이야기**: 활성 사건을 시간 순서로 살펴보고 연결된 채팅 근거로 이동합니다.
- **찾기**: 현재 위키와 채팅의 문자열을 찾아 바꿉니다. 실행 전 결과 범위를 확인하세요.
- **로그**: 자동 분석, 수동 저장, 휴지통 이동과 오류 기록을 확인합니다. 프롬프트 본문이나 API 키는 표시하지 않습니다.
- **설정**: 위키 작업에 보조 모델을 사용할지 메인 모델을 사용할지 선택합니다.

## 문서 편집과 안전장치

왼쪽 파일 트리에서 문서를 고르고 **타입**과 **이름**을 수정한 뒤 본문을 편집합니다.

- **저장**: 현재 제목, 유형과 Markdown 본문을 저장합니다. 기존 문서를 덮어쓰기 전 버전은 history에 보존됩니다.
- **되돌리기**: 저장하지 않은 현재 편집 내용을 마지막으로 불러온 상태로 되돌립니다.
- **로어북에 복사**: 저장된 문서를 캐릭터 로어북의 비활성 항목으로 복사합니다. 저장하지 않은 변경이 있으면 먼저 저장해야 합니다.
- **삭제**: 일반 문서는 휴지통으로 이동합니다. 확정 사건 문서는 읽기 전용이며, 명시적인 확인 뒤 영구 삭제됩니다.

문서 이름이나 유형을 바꿔도 내부 ID는 유지됩니다. 직접 연결된 위키 링크는 안전하게 갱신되며, 동시에 다른 편집이 발생해 내용 hash가 달라지면 저장을 중단해 덮어쓰기를 방지합니다.

## 문서 유형

- **캐릭터**: 현재 상태, 관계, 지식, 목표와 중요한 작중 행적
- **장소**: 공간의 성격, 위치, 변화와 관련 인물
- **세력**: 집단의 목적, 구성원, 관계와 영향력
- **사물**: 중요한 물건, 소유자, 상태와 기능
- **개념**: 규칙, 현상, 설정과 추상적인 세계관 정보
- **현재 장면**: 지금 진행 중인 시점·장소·참여자와 직전 상태
- **기타**: 위 유형에 맞지 않는 지속 정보
- **사건**: 확정된 변화의 근거 기록. 자동으로 만들며 일반 편집은 허용하지 않습니다.

## 컨텍스트 정책

일반 문서를 우클릭하면 다음 응답에 포함되는 방식을 바꿀 수 있습니다.

- **항상 컨텍스트에 포함**: 관련도와 관계없이 필수 문서로 사용합니다.
- **관련 있을 때 포함**: 현재 입력과 제목·본문·위키 링크가 관련될 때만 후보가 됩니다. 기본값입니다.
- **자동 컨텍스트에서 제외**: 자동 조회에서는 제외하지만 사용자가 직접 선택해 참고할 수 있습니다.

필수 문서가 고정된 문서 수나 토큰 한도를 넘으면 일부를 몰래 버리지 않고 오류로 알립니다.

## 파일 트리와 건강도

- **문서**는 현재 정본 문서 수입니다.
- **끊어진 링크**는 대상 문서를 찾지 못한 `[[위키 링크]]` 수입니다.
- **연결 없음**은 다른 현재 문서와 연결되지 않은 정본 수입니다.

이 진단은 현재 파일에서 계산한 안내 정보이며 원문을 자동으로 고치지 않습니다. 파일을 외부 편집기에서 수정했다면 메모리 위키를 다시 열어 최신 상태를 불러오세요.

## 위키 관리자 명령

하단 명령 입력창은 자연어로 여러 문서를 한 번에 만들거나 수정하는 직접 편집 도구입니다. 예를 들어 “등장인물별 문서를 만들고 현재 관계를 반영해”처럼 원하는 결과를 구체적으로 적을 수 있습니다.

- 사용자 명령이 편집 내용의 최우선 지시입니다.
- AI는 제목과 본문 초안을 만들지만 실제 파일 경로, ID와 frontmatter는 프로그램이 검증하고 결정합니다.
- 변경 전 내용은 history 또는 trash에 보존되고, 현재 hash가 예상과 다르면 충돌한 문서만 중단합니다.
- `Ctrl+Enter`로 실행할 수 있습니다. 실행 결과와 실패 항목은 명령 패널과 로그에서 확인합니다.

## 문제가 생겼을 때

1. 상단 상태 메시지와 **로그**에서 실패 이유를 확인합니다.
2. 저장 버튼이 비활성이라면 제목과 본문이 비어 있지 않은지, 사건 문서처럼 읽기 전용인지 확인합니다.
3. 로어북 복사가 비활성이라면 현재 문서를 먼저 저장합니다.
4. 외부 편집 내용이 보이지 않으면 메모리 위키를 닫았다가 다시 엽니다.
5. 충돌 경고가 나타나면 현재 파일을 다시 불러온 뒤 변경 내용을 비교하여 적용합니다.

Markdown 파일이 서사 메모리의 정본입니다. 생성 캐시나 화면 진단은 언제든 다시 만들 수 있으며 정본을 대신하지 않습니다.
