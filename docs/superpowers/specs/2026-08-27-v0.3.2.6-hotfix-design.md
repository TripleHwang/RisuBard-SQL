# RisuVault v0.3.2.6 Hotfix Design

## Scope

This hotfix fixes three regressions reported against v0.3.2.5:

1. A character selected from the metadata-first shell can render as a shallow summary with empty description, first message, creator notes, lorebook and additional assets.
2. `Loading saved settings…` replaces the chat surface and changes its width while deferred settings are loading.
3. RisuRealm rejects the current production response and reports `Unable to load RisuRealm results.`

The release must also stop shallow character/chat summaries from overwriting canonical SQL bodies and offer a selective repair for bodies already collapsed by that bug.

## Character selection contract

- Clicking a character starts one selection transaction identified by the character ID.
- The existing circular loading overlay remains visible while the client loads the full character body, the selected chat body and the bounded recent message window.
- `selectedCharID` does not change until all required reads succeed and the selection is still the newest user intent.
- The old screen remains mounted under the overlay, so there is no blank intermediate character.
- A failed read closes the overlay, keeps the prior selection, and shows a retryable error. It never marks a summary as fully loaded.
- Long histories remain bounded: selection loads only the latest message page. Older messages continue to prepend through continuous-history scrolling.

## SQL non-destructive persistence

Character and chat commits distinguish row metadata from canonical body replacement.

- Metadata fields such as position, name, image, chat note and folder can be updated from summaries.
- Character extension nodes and tags are replaced only when the runtime character has `detailsLoaded === true`.
- Chat extension nodes are replaced only when the runtime chat has `detailsLoaded === true`.
- Character hydration returns chat summaries with `detailsLoaded === false`.
- A targeted chat endpoint loads the chat extension body before the recent message page is attached.
- Old clients that omit the new preservation flag keep the current full-replacement behavior for protocol compatibility.

This avoids hydrating every character merely to reorder the sidebar and keeps startup performance metadata-first.

## Selective repair

The server inspects the preserved `database/pre-sql-migration-v1.bin` only when a loaded SQL character is suspiciously collapsed.

- A body is repairable only when the current SQL extension lacks all meaningful character-body fields and the backup contains the same `chaId` with at least one meaningful value.
- Repair replaces only that character's extension body and tags.
- Current SQL chats and messages, other characters, global settings and assets are not rolled back.
- Asset references restored from the character body continue to point at the existing KV asset store.
- If the backup is missing or has no richer matching character, selection fails visibly instead of inventing empty defaults.

## Stable deferred-settings UI

- The main chat/character surface is not replaced by `DeferredStartupGate`.
- Settings-dependent pages render their loader inside their own existing bounds.
- Loading feedback uses a centered circular overlay/skeleton and never contributes intrinsic width to the app flex row.
- Safe metadata-first surfaces remain usable while deferred global settings load.

## RisuRealm compatibility

The Realm normalizer accepts the live production schema while retaining bounded cache safety:

- `haslore` and `hasLore` map to one boolean.
- numeric `0/1` flags map to booleans.
- empty `viewScreen` maps to `none`.
- missing/nullable optional metadata receives bounded defaults.
- image data/blob URLs remain rejected and the 100-card/1 MiB cache limits remain unchanged.

## Verification

Focused behavioral tests cover:

- the captured production Realm payload shape;
- metadata-only character/chat commits preserving existing extension nodes;
- full selection waiting for character, chat and recent messages before changing selection;
- failed selection retaining the prior screen;
- selective repair preserving chats/messages;
- stable loading-gate layout and menu-local loading.

The release gate then runs the focused suites, `pnpm check`, the normal client/server suites, build, release compatibility and performance-contract tests before PR and release publication.
