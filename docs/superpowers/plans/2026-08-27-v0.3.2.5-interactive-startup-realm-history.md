# RisuVault v0.3.2.5 Interactive Startup, Realm Cache, and Continuous History Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the shallow Node SQL shell genuinely interactive, serve the default RisuRealm feed from a bounded persistent SWR cache, and replace broken message pages with continuous bounded history scrolling.

**Architecture:** Keep shallow SQL metadata and full deferred normalization as separate readiness phases. Remove the global inert gate while retaining feature-local mutation guards, then run deferred hydration immediately after first paint. Cache only the public default Realm feed through the existing persistent KV layer, and keep SQL history chunks internal while a 60/40-row bidirectional virtual DOM window presents one continuous conversation.

**Tech Stack:** Svelte 5, TypeScript, Vitest, Node SQLite, existing `persistentKv`, SQL runtime hydration, and saver-mode cache/window infrastructure.
