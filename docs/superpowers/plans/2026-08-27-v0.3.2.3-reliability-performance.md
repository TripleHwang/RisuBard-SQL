# RisuVault v0.3.2.3 Reliability and Performance Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship v0.3.2.3 with one-time server-owned SQL migration, metadata-first fast startup, local/LAN CharX imports above 256 MiB without large-asset loss, working installed-plugin updates, and correct next-page scroll positioning.

**Architecture:** Keep relational SQLite and file-native assets, but match Haejeok's observable startup pipeline: one shallow canonical read, immediate shell reveal, on-demand character/chat/message hydration, and post-paint parallel domain loading. Move legacy migration entirely behind a dedicated server operation, make bootstrap revision-cached and shallow, preserve direct streamed CharX transport while replacing fixed archive/asset caps with disk-backed admission and decompression safeguards, and fix the two UI regressions at their existing action boundaries.

**Tech Stack:** TypeScript, Svelte 5, Node.js 22 `node:sqlite`, Express, fflate streaming ZIP, Vitest, Vite.

---

## File ownership map

- SQL/startup worker owns `server/node/relational-sqlite.cjs`, a focused migration service/route module if extraction is required, `server/node/server.cjs` SQL wiring, `src/ts/storage/sql/nodeSqliteStorage.ts`, `src/ts/storage/sql/sqlBootstrap.ts`, `src/ts/bootstrap.ts`, and their focused tests.
- CharX worker owns `server/node/charx-import.cjs`, `server/node/charx-import-route.cjs`, CharX tests, and only the CharX-specific client transport if required.
- UI worker owns `src/ts/plugins/pluginUpdate.ts`, `src/ts/plugins/plugins.svelte.ts`, `src/lib/Setting/Pages/PluginSettings.svelte`, `src/lib/ChatScreens/DefaultChatScreen.svelte`, and focused plugin/pagination tests.
- Main integrator owns version files, patch notes, cross-subsystem conflicts, performance-report updates, complete verification, and commits.

Parallel workers do not stage or commit because they share one Git index. The main integrator reviews and commits each subsystem after its focused tests pass.
