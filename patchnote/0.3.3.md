# RisuVault 0.3.3

## 시작이 몇 분씩 걸리던 문제

레거시 데이터를 SQL로 옮기는 작업이 요청 하나로 되어 있어, 약 35 MB가 넘는 데이터는 서버가 `SQL commit is too large`로 거부했습니다. 거부되면 레거시 데이터로 되돌아가 앱은 정상 동작했지만, 그 실패를 아무도 알려주지 않아 켤 때마다 같은 시도를 반복했습니다.

- 마이그레이션을 여러 요청으로 나눠 보냅니다. 실측으로 49 MB / 메시지 72,000개 / statement 361,397개가 19개 요청, 17.8초에 완료됩니다.
- 마지막 조각이 도착해야 데이터베이스가 완료 표시됩니다. 중간에 끊긴 마이그레이션은 다음 실행이 "미완"으로 알아보며, 빈 데이터베이스나 완료된 데이터베이스로 오인하지 않습니다.
- 진행 상황을 표시합니다.
- 마이그레이션이 실패하면 알려줍니다. 레거시 데이터로 계속 사용할 수 있는 동작은 그대로입니다.

## 진단

- 시작 구간별 소요 시간을 콘솔에 한 줄로 기록합니다. 어느 단계가 오래 걸리는지 라벨만 보고 추측하지 않아도 됩니다.
- 서버에서 `RISUVAULT_BOOTSTRAP_PROFILE=1`을 설정하면 초기 데이터 응답을 구간별 시간과 크기로 나눠 기록합니다.
- 서버 오류 처리가 오류를 기록하고, 오류가 가진 상태 코드를 유지합니다. 이전에는 모두 500으로 바뀌고 아무 곳에도 남지 않았습니다.

## 저장

- 루트 항목을 필요할 때 불러오도록 미룰 수 있게 했습니다. 불러오지 않은 항목이 삭제된 항목으로 취급되지 않도록 막는 검사를 함께 넣었습니다.
- 플러그인 저장소를 첫 응답에서 제외하고 플러그인 화면을 열 때 불러옵니다.

## 기타

- RisuBard 0.9.2와 0.9.4의 변경사항을 반영했습니다.
- 채팅 목록 병합 시 일부만 불러온 채팅이 잘린 채로 병합되던 문제를 고쳤습니다.
- 자동 자산 정리가 아직 불러오지 않은 캐릭터의 이미지를 참조 없는 것으로 보고 삭제할 수 있던 문제를 고쳤습니다.

이 릴리스는 0.3.1을 기준으로 다시 쌓았습니다. 0.3.2.x 계열은 사용하지 않습니다. 중요한 데이터는 최신 백업과 함께 사용해 주세요.
